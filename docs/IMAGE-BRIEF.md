# Image brief — `/origin`

> **v2 (2026-09-18) — supersedes §0 prompts and §4 pipeline.** The v1 §0 renders came out on
> light-grey grounds and read as dull once duotoned. The shipped v2 set is generated by
> `scripts/generate-images.py` (same subjects, prompts hardened to force a genuinely dark,
> flat near-black ground, one accent, no added props) and post-processed by
> `scripts/process-images.sh` (per-image palette snap to exact brand hexes → WebP
> 600/900/1366w, no duotone, no baked opacity — faintness is CSS-only). Sources live in
> `imgs/v2/`. Total 1366w weight ~156 KB. Everything below is kept for reference.

> **v3/v4 (2026-09-18) — SHIPPED. America-themed line art on pure black.** New direction:
> **American civic iconography**, one image per beat, each echoing that beat's idea.
>
> **What went wrong before (all fixed):**
> 1. *Blur* — the generator caps at ~1376 px; a 2×-DPR display wants ~3000 px, so the browser
>    upscaled ~2.3× and curves turned to mush. Fixed by upscaling to **2048w** and then snapping
>    to the palette, which re-hardens the edges (measured: plain upscale leaves a grey halo;
>    upscale + palette-snap is vector-crisp).
> 2. *"Not black"* — the old ground was `#16130E`, a **warm** near-black that reads as dark
>    brown-grey, and dimming it in CSS turned gold into mud. Ground is now **pure black
>    `#000000`**, images render at **opacity: 1**, and the scrim is black alpha (`rgba(0,0,0,…)`).
> 3. *Light mass* — solid-filled subjects made the frame read bright. Subjects are now drawn as
>    **thin line work**, so each frame stays mostly empty black.
>
> **Style bible (prepend to every prompt):**
> ```
> High-contrast flat LINE-ART poster, screen-print / woodcut, American civic poster tradition.
> The ENTIRE background is flat solid PURE BLACK #000000 — true black, NOT grey, NOT brown,
> no gradient, no vignette, no texture, no grain, no paper, no blur. Draw the subject as clean
> thin confident OUTLINE line-work, never as big solid filled blocks, so the frame stays mostly
> empty black. Hard crisp vector edges: no shading, no soft shadows, no glow, no 3D, no
> photorealism, no halftone. Palette strictly pure black ground plus at most two of bone
> #F1ECE0, blood red #FF5A5F, gold #E5C158, flag blue #4169E1. The subject is small and sits
> low in the frame, fully inside the frame and never cropped; keep the top two-thirds as empty
> black space. Absolutely NO text, NO words, NO lettering anywhere. Landscape 16:9.
> ```

## 0. Generation prompts

### Style bible — prepend to every prompt below

```
Neobrutalist editorial illustration, dark and high-contrast, restrained.
Ground color #16130E (near-black ink). Single accent per image, never more than two.
Palette limited to: #F1ECE0 (paper/bone), #FF5A5F (blood red), #E5C158 (gold),
#4169E1 (flag blue). No gradients. No glassmorphism. No soft drop shadows.
No glow, no bloom, no lens flare. Flat or hard-lit forms, heavy contrast,
poster/woodcut/linocut sensibility — closer to a WPA propaganda print or a
Greek red-figure vase silhouette than a photo-real render.
Huge negative space at top or bottom third for overlaid display type.
Grain/noise texture at very low opacity only, no other decoration.
No mascots, no cute characters, no confetti, no sparkle, no 3D render sheen.
Square-ish or portrait crop, mobile-first (aspect 4:5 or 1:1).
```

Append to every prompt to keep it out of AI-slop territory:
```
--no gradient, --no glow, --no soft-shadow, --no photorealistic skin, --no stock-photo lighting
```

Nothing else in frame. Massive empty space above for a headline. Linocut/woodcut texture in the stone grain.

### Beat 4 — the threat to the polis (`beat-4`)

### Beat 5 — the drift of the word (`beat-5`)

Works as a static hero and as a social share card.


## 1. What these images are for

Each beat in `/origin` is one sentence-sized idea on a mostly-black screen. The image is a **texture behind the text**, not an illustration next to it. If a reader can describe the picture in detail after reading the beat, the picture won, and the words lost. Target: the image should be felt, not examined.

## 4. The color pipeline — generation drift is not acceptable, post-process every asset

AI generators drift off exact hex values even with a hex-locked prompt. **Do not ship a generated image straight out of the model.** Every beat image gets the same deterministic post-process, in this order:

1. **Desaturate to grayscale.**
2. **Duotone remap:** shadows → `#16130E` (ink), highlights → the beat's single assigned accent (gold `#E5C158` for beats 1/4/7, blood `#FF5A5F` for beats 2/6, flag blue `#4169E1` for beat 5's connecting line only, bone `#F1ECE0` for beat 3's filled seats). One accent per image, exactly as the style bible specified — if the duotone remap produces a second accent by accident, redo the remap, don't ship it.
3. **Reduce overall image opacity to 35%** baked into the export (not left to CSS) so a slow device never renders a flash of full-strength artwork before CSS opacity applies.
4. **Add the same low-opacity noise texture already used site-wide** (the SVG turbulence filter in `app.css`) — do this once at the CSS layer, not per-image, so it stays consistent and isn't re-encoded into every WebP.

This pipeline is a Figma/Photoshop/ImageMagick job, not a code job — but it is **mandatory before any asset is committed**, and it's the reason the generation prompts alone were insufficient: they get you an on-theme *shape*, this step gets you an on-brand *color*.

## 5. Placement — full-bleed behind text, never beside it

```
┌─────────────────────────┐
│                         │  ← negative space, 40% of frame height
│                         │     (image's darkest/emptiest region lives here —
│                         │      pick the crop so this zone has the least detail)
│  BEAT TEXT RENDERS HERE │  ← Anton/Space Grotesk overlay, this zone
│  (2-4 lines max)        │     always sits over the image's calmest area
│                         │
│                         │  ← rest of frame, image detail lives here
│  [ skip → ]             │
└─────────────────────────┘
```

- Image is a **full-bleed background** of the beat's viewport (`position: absolute; inset: 0; object-fit: cover; z-index: 0`), never an inline `<img>` sitting next to a text block. Text is `position: relative; z-index: 1`.
- **Crop discipline:** every master must be composed so its emptiest 40% lands where beat copy will sit (top third for beats that read top-down, per the per-beat notes below). This is an art-direction note for whoever runs the generator/crops the master — verify by placing the actual beat copy over the actual crop before approving the asset, not by eyeballing the image alone.
- A **contrast scrim** sits between the image and the text on every beat, non-negotiable: `background: linear-gradient(to bottom, rgba(22,19,14,0.55), rgba(22,19,14,0.15) 40%, rgba(22,19,14,0.75))` or equivalent, tuned per-beat so body text at `#F1ECE0` on `app.css`'s existing weight/size clears **4.5:1 contrast minimum** against whatever sits directly behind it. Verify with an actual contrast checker against the rendered composite, not the raw image.

| Beat | Text zone | Image's calm zone | Notes |

## 6. Component integration

Extend the existing `Beat.svelte` (per `BUILD-PLAN.md` §7) with an `image` prop and the client-only mount guard already established site-wide for entrance effects:

```svelte
<!-- Beat.svelte -->
<script lang="ts">
  let { prompt, image, index }: { prompt: string; image: string; index: number } = $props();
  let mounted = $state(false);
  onMount(() => { mounted = true; });
</script>

<section class="beat" class:mounted aria-hidden={false}>
  <picture class="beat-bg" aria-hidden="true">
    <source
      srcset="/images/origin/{image}-600.webp 600w,
              /images/origin/{image}-900.webp 900w,
              /images/origin/{image}-1200.webp 1200w"
      sizes="100vw"
      type="image/webp" />
    <img src="/images/origin/{image}-900.webp" alt="" loading={index === 0 ? 'eager' : 'lazy'} />
  </picture>
  <div class="beat-scrim"></div>
  <div class="beat-copy">
    <slot />
  </div>
</section>
```

- **`alt=""` and `aria-hidden="true"` on the whole `<picture>`** — these images are decorative texture, never content. A screen reader must never announce them; the beat's *text* is the content and is read normally.
- **No entrance transition on the image itself.** Per the engineering constraint ("no Svelte transitions on anything that renders during the SSR initial pass" + client-only mounting for entrance effects), the image renders at its final 35%-baked-in opacity immediately — it does not fade in separately from the text. Only the *text* gets the existing `rise` keyframe treatment (already defined in `app.css` for the teaser's `.mark`/`.question`/`.soon`), gated behind `{#if mounted}` exactly as the current codebase already does. Animating the image and the text on separate timers would blow the 400ms screen budget and add a second thing to track under `prefers-reduced-motion`.
- **`prefers-reduced-motion`:** no separate handling needed for the images themselves since they carry no transition — the existing global reduced-motion media query in `app.css` already zeroes any transition duration site-wide, which covers it for free.

## 7. Loading strategy

`/origin` is a 7-step linear read with no branching, so loading is predictable — exploit that instead of loading all 7 up front or waiting on each one individually.

- **Beat 1's image:** preload via `<link rel="preload" as="image">` in the route's `<svelte:head>`, `fetchpriority="high"`. It must be visible the instant the route mounts.
- **Beats 2–7:** each beat, on mount, triggers a `<link rel="prefetch">` for the *next* beat's `900w` WebP (predictive one-ahead prefetch — the reader is about to advance, and 3-second-per-question quiz-speed readers will out-run a lazy `loading="lazy"` fetch on a slow connection). This is a small `onMount` hook in `Beat.svelte`, not a separate service.
- **The `og-origin` JPEG** is fetched by social crawlers only, never by the app itself — no preload needed, just correct `<meta property="og:image">` wiring in `/origin`'s `<svelte:head>`.
